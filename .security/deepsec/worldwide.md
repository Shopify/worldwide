# worldwide

## What this codebase does

`worldwide` is a public Ruby gem (Ruby 3.2+) for localization and mailing-address handling. It also
ships a small TypeScript package in `lang/typescript/` (`@shopify/worldwide`). The gem has no web
server, no database, no network client at runtime and no authentication. It is a library that a host
application calls with strings that its own users typed.

- `lib/worldwide/`: regions and subdivisions (`regions.rb`, `region.rb`, `regions_loader.rb`), postal
  codes (`zip.rb`), address checks (`address.rb`, `address_validator.rb`), phone numbers (`phone.rb`),
  locales and plural rules (`locale.rb`, `locales.rb`, `plurals.rb`, `cldr.rb`), currencies, numbers,
  dates and time zones, and the `ruby-i18n` setup (`config.rb`, `ruby_i18n_config.rb`).
- `lang/typescript/src/`: splits and joins extended address fields. `lang/typescript/rollup-plugin-regions-yaml/`
  turns the region YAML files into one bundle at build time.
- `rake/`: maintainer tasks that pull Unicode CLDR data and postal-code data into `data/`. They run on
  a maintainer's machine, never inside a host application.
- `.github/workflows/`: CI, a changeset-based npm release, and a CLA check.

## Auth shape

There is no authentication or authorization in this repository, so do not report a missing auth check.
The trust boundaries are different:

- **Caller input**: every public method that takes a country code, province code, zip, phone number,
  locale or free-text address field treats it as untrusted text. Entry points are `Worldwide.region`,
  `Worldwide::Regions#region`, `Worldwide::Zip.normalize`, `Worldwide::Zip.find_country`,
  `Worldwide::AddressValidator.errors`, `Worldwide::Phone.new`, `Worldwide::Locale#name` and the
  TypeScript `splitAddress1`, `splitAddress2`, `concatenateAddress1` and `concatenateAddress2`.
- **Repository data**: files under `data/` are trusted input, generated by the rake tasks and reviewed
  in PRs. Loading code must read them from the fixed roots in `Worldwide::Paths`.
- **CI identity**: `npm-release.yml` holds `id-token: write`, `contents: write` and a repository token.

## Threat model

The most likely harm is to a host application that passes untrusted text into this library. Rank by impact:

1. **Code or file access driven by input**: any `eval`, `send`, `constantize`, `Regexp.new`, file read
   or YAML load whose argument can contain caller input. Values that name a file or a method must be
   checked against a known list first (`Worldwide::Locales`, `Worldwide::Regions`).
2. **Denial of service**: a regular expression, loop or normalization step whose cost grows faster than
   linearly with the length of a caller string. Postal-code regexes come from region data and run on user
   input in `Region#passes_country_zip_regexp?`, `Zip.normalize` and the TypeScript regex split.
3. **Wrong validation result**: an address or phone number that is accepted or rejected wrongly
   because of Unicode handling (full-width digits, zero-width characters, `RESERVED_DELIMITER`).
4. **Supply chain**: a workflow, dependency or pulled data file that changes what ships to RubyGems or npm.
5. **Unsafe deserialization**: `YAML.load_file` or `Marshal` on data that is not under `data/`.

## Project-specific patterns to flag

- **Input in a lookup key**: `Regions#region` upcases the code and uses it as a hash key. Flag new
  lookups that build a file path, a constant name or a method name from `code:`, `cldr:` or `name:`.
- **YAML loading**: the code reads YAML from the roots in `Worldwide::Paths`, mostly with
  `YAML.safe_load_file`. Flag `YAML.load`, `unsafe_load` or `load_file` calls added for data that could
  come from outside `data/` (`regions_loader.rb`, `currency.rb`, `locales.rb`).
- **Dynamic code loading**: `Plurals.load_locale_rule` reads a rules file by locale code and evaluates
  it. Flag any other `eval`, `instance_eval`, `class_eval` or `send` with a computed name, and any change
  that lets the locale string reach that path without `Worldwide::Cldr.fallbacks`.
- **Regex built from data**: `Zip.regex_for` and `Region#passes_country_zip_regexp?` call `Regexp.new`
  on `zip_regex` or `partial_zip_regex`. Flag a new regex with nested quantifiers or alternation of
  overlapping patterns, and any regex built by interpolating caller text without `Regexp.escape`.
- **Phone parsing**: `Phone#parse_number` and `split_extension` pass caller text to `Phonelib`. Flag
  changes that skip `transliterate` or accept a number of unbounded length.
- **I18n interpolation and exceptions**: `missing_interpolation_argument_handler` and
  `I18nExceptionHandler` decide what a missing key renders. Flag a handler that echoes caller text into
  output that a host may treat as HTML, or that raises with caller text in the message.
- **Workflows**: flag any new `pull_request_target`, an action pinned to a tag instead of a commit SHA,
  `${{ github.event.* }}` used inside a `run:` script, or a secret passed to a step that runs PR code.
- **Rake pullers**: `Postal::Puller#download` and `Cldr::Puller` fetch remote data. Flag URLs built
  from environment variables or arguments without a fixed host, and files written outside `data/` or
  `rake/postal/vendor/`.

## Known false-positives

- `data/**`: country, region and CLDR reference data, and the generated `plurals.rb` rule files that
  `Plurals.load_locale_rule` reads. Strings that look like secrets, tokens, emails or regexes here are
  postal formats, names and sample values. The scan leaves this folder out.
- `test/**` and `*.test.ts`: fixtures use synthetic addresses and phone numbers, and call internals with
  `send` on purpose.
- `Region#send(:private_method)` and `Zip` calls to `country.send(:valid_normalized_zip?, ...)`: the
  receiver is always a `Region` and the method name is a literal in the source.
- `Regexp.new` over `zip_regex` or `partial_zip_regex`, and `new RegExp` in the TypeScript
  `getAddress1Regex`, when the pattern comes from the region YAML files and not from the caller.
- `yaml.load` in `rollup-plugin-regions-yaml/index.ts`: it parses the repository's own region files at
  build time, not caller input.
- `.github/workflows/cla.yml`: it runs on `pull_request_target` and uses a first-party action pinned to
  a tag. It checks out no PR code and runs no PR-controlled script, so the trigger alone is not a finding.
- `rake/**` and `bin/**`: maintainer tooling that a person runs by hand. `worldwide.gemspec` leaves
  `rake/`, `test/` and `lang/typescript/` out of the packaged gem.
