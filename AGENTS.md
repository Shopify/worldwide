# Contributing to Worldwide

Worldwide is a public Ruby gem for localization and address handling: region and country data, address validation, normalization and formatting, postal codes, currencies, numbers, names, lists, dates and time zones, and phone numbers. It also contains the public `@shopify/worldwide` TypeScript package, which splits and joins extended address fields.

## Keep contributions public

- Use public sources and synthetic address examples. Use a published address for a public institution only when the example needs a real location.
- Do not include customer or merchant data, internal links, private tickets, logs, screenshots, credentials, or unpublished findings. This rule also applies to PR text, comments, commit messages, fixtures, generated data, and CI output.
- Cite the public source for data changes. Prefer the relevant postal authority, government agency, ISO list, Unicode CLDR, or IANA time zone database. Check that readers can open the source without private access. Check the license and keep any required attribution.

## Find the right file

| Change | Start here |
| --- | --- |
| Address layouts, postal rules, zone codes, country settings | `data/regions/<CC>.yml`, `lib/worldwide/region.rb`, `lib/worldwide/zip.rb` |
| Region labels and translations | `data/regions/<CC>/`, `data/cldr/`, `data/other/` |
| CLDR corrections | [`rake/cldr/patch.rb`](rake/cldr/patch.rb), [`rake/tasks/cldr.rake`](rake/tasks/cldr.rake) |
| Postal prefix imports | [`rake/postal/README.md`](rake/postal/README.md) |
| Currencies, numbers, names, lists, times, punctuation | `lib/worldwide/currency.rb`, `numbers.rb`, `names.rb`, `lists.rb`, `time_formatter.rb`, `punctuation.rb` |
| Phone numbers | `lib/worldwide/phone.rb`, which wraps `phonelib` |
| Locale and `I18n` setup | `lib/worldwide/locale.rb`, `locales.rb`, `config.rb`, `ruby_i18n_config.rb` |
| TypeScript address code | [`lang/typescript/`](lang/typescript/) |

## How the gem is organized

The gem is data-driven. Its data lives in `data/`:

- `data/regions/`: one YAML file per country or territory, with its zones, address formats and postal code rules.
- `data/cldr/`: Unicode CLDR data, generated by the CLDR rake tasks (see [Update CLDR data](#update-cldr-data)).
- `data/world.yml`: the region hierarchy (continents and subregions); `data/country_codes.yml`: alpha-3 and numeric codes.
- `data/extant_outcodes.yml`: the GB outcodes that exist, which `Zip.outcode` uses to guess the outcode of a partial postcode.

The `Worldwide` module is the entry point: `Worldwide.region(code:)` (or `cldr:` or `name:`), `Worldwide.address(...)`, `Worldwide.currency(code:)`, `Worldwide.locale(code:)`, and `Worldwide.numbers`, `names` and `lists`. `Region` covers countries, territories, provinces and states, and validates at both the country and the zone level. `Address` validates, normalizes and formats an address, with `AddressValidator`. `Zip` normalizes and validates postal codes.

The runtime dependencies are `activesupport`, `i18n` and `phonelib`. `ruby-cldr` is only for the CLDR rake tasks.

## Code conventions

- Start every Ruby file with `# frozen_string_literal: true`. Style follows `rubocop-shopify`.
- Load YAML data lazily, and cache it in an instance variable.
- Accept a `locale:` argument that defaults to `I18n.locale`.
- Put tests under `test/worldwide/`, mirroring `lib/worldwide/`. They use Minitest with `mocha` for mocks and `minitest-focus`.

## Make the change easy to review

- Keep the change to one behavior or one related group of countries. Split unrelated cleanup and dependency updates into separate PRs.
- Match nearby YAML key order, indentation, and quoting. For generated CLDR data, change the patch or generator and include the matching output. Run `bundle exec rake cldr:data:generate_paths` after you add, move, or remove indexed data files.
- Treat changes to canonical codes, defaults, locale scripts, fallback rules, and validation as API changes. Show the old and new output. Keep historical codes as lookup alternates when appropriate. Test lookup by both codes and check the value the API returns.
- For postal changes, test old and new formats, normalization, and invalid input. Check that examples match the rule. An example can also affect the reported postal code type. For address layouts, check both `edit` and `show` where applicable. See [Address format strings](docs/address_format_strings.md).
- Add focused Minitest coverage next to related tests. For country-specific tests in `test/worldwide/regions/`, use `<cc>_test.rb` and a class such as `PaTest`. If shared region data changes, check its effect on the TypeScript package too.

## Run checks

### Ruby

Use `.ruby-version` for local setup. Check [`worldwide.gemspec`](worldwide.gemspec) for the supported Ruby minimum and [Ruby CI](.github/workflows/ci.yml) for the test matrix. Do not assume the oldest Ruby in CI is the supported minimum.

```sh
bundle install
bundle exec ruby -Itest test/worldwide/regions/pa_test.rb  # example focused test
bundle exec ruby -Itest test/worldwide/region_test.rb -n test_method_name  # one test
bin/test
bin/style  # bundle exec rubocop; pass -a to autocorrect
```

`bundle exec rake` runs the tests and RuboCop together. `bin/console` opens a console with the gem loaded.

Run `bin/test-cldr-rake-tasks` from a clean checkout to check that the full CLDR pipeline reproduces the committed data. The script downloads data and reports unexpected changes to the working tree.

### TypeScript

For changes that affect TypeScript, use the Node and pnpm versions in [TypeScript CI](.github/workflows/ci-typescript.yml):

```sh
cd lang/typescript
pnpm install
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

`pnpm format` formats the package, and `pnpm test:watch` reruns the tests on change.

## Update CLDR data

Do not edit `data/cldr/` by hand. To import a new CLDR release, run these tasks in order:

1. `bundle exec rake cldr:data:clean` removes the existing CLDR files.
2. `bundle exec rake cldr:data:import` downloads CLDR (the version in `data/cldr.yml`) into `vendor/` and converts it to YAML. It takes several minutes. `VERSION=42` picks another release, and `COMPONENTS=Units,Calendars` imports only some components.
3. `bundle exec rake cldr:data:patch` applies the fixes in [`rake/cldr/patch.rb`](rake/cldr/patch.rb) and writes `data/cldr/`.
4. `bundle exec rake cldr:data:generate` generates locale data such as date and time formats and missing plurals.
5. `bundle exec rake cldr:data:generate_paths` writes the file indices.

### Patch a CLDR value

To fix a CLDR value, add a `patch_subdivisions` or `patch_file` call to `rake/cldr/patch.rb`, run `bundle exec rake cldr:data:patch`, and commit the patch with the data it changes. For example:

```ruby
# Remove ² markers from Spanish subdivisions in Portuguese
patch_subdivisions(:pt, [
  [:esna, "Navarra²", "Navarra"],
  [:esri, "La Rioja²", "La Rioja"],
])
```

Report the issue upstream at https://unicode-org.atlassian.net when it applies to CLDR itself. `vendor/` is ignored by git; do not commit it.

## Open the PR

- Use the [PR template](.github/pull_request_template.md). State the problem, why you chose this fix, which behavior changes, and what you tested. Include public sources, a small reproduction, or a before-and-after example when useful.
- Add an entry under `Unreleased` in [`CHANGELOG.md`](CHANGELOG.md) for every change except routine updates such as dependency bumps. Add the public PR link once it exists. Leave the version bump to the release unless a maintainer asks for both in the same PR.
- For a TypeScript change that affects package users, add a changeset with `pnpm changeset` from `lang/typescript`. See the [package README](lang/typescript/README.md) for the release process.
